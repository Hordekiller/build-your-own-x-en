About

Max Bernstein (who has worked on real compilers like OCaml and CMUCL) builds a Lisp interpreter in OCaml across a series of articles, adding closures, macros and runtime simulation step by step.

What you'll learn

  • A base interpreter: atoms, lists, simple eval; then symbols and variables
  • Lambda functions with nested environments, let*, error handling with Error values
  • Macros, final optimizations and runtime cost discussion

Core idea

Each article lives in its own partN folder: parsing/eval basics, symbols and variables, lambda and nested environments, let*, error representation in the runtime, macros, and a closing discussion of optimization and runtimes.

OCaml(* evaluation over an abstract data type *)
let rec eval env = function
  | Atom a -> List.assoc a env        (* find variable in env *)
  | Number n -> Number n
  | List (Atom "quote" :: [x]) -> x   (* quote: no evaluation *)
  | List (Atom "if" :: [c; t; f]) ->
      if eval env c = Bool true then eval env t else eval env f
  | List (Atom "lambda" :: [params; body]) ->
      (* closure: body + params + environment *)
      Closure (params, body, env)
  | List (Atom fn :: args) ->
      let f = eval env (Atom fn) in
      let args' = List.map (eval env) args in
      apply f args'
  | _ -> raise (Invalid_argument "invalid expression")

Why it matters

For OCaml lovers: good conceptual depth, complete code and comparisons with other implementations - then move to a C compiler to feel the weight of a real one.
