Implementing promises from scratch (TDD way)

About

Write a Promise implementation test-first: tests spell out the exact behavior (settle once, chaining, errors), then the minimal code passes them. Uses a jest-like test runner step by step.

What you'll learn

  • Writing behavior specs before implementation
  • resolve/then chains and value passing
  • reject/catch semantics, including throw-in-executor

Core idea

The first tests define resolve, value delivery, and chained then with computed values; later tests demand catch and that a throw inside the executor behaves as a rejection.

JavaScript// test: resolve gives the value
test('resolve delivers the value', () => {
    const p = new MyPromise((resolve) => resolve(42));
    return p.then(value => {
        expect(value).toBe(42);
    });
});

// test: chains work
test('then chains', () => {
    const p = new MyPromise((resolve) => resolve(2));
    return p
        .then(v => v * 10)
        .then(v => v + 1)
        .then(v => expect(v).toBe(21));
});

Why it matters

Promises have precise, specifiable behavior - the perfect project to practice red-green-refactor.
