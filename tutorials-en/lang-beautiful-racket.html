Beautiful Racket: How to make your own programming languages with Racket

About

Matthew Butterick's Beautiful Racket takes a different route: instead of a standalone interpreter, you define a new #lang using Racket's meta-circular facilities - syntax and behaviour are declared, not implemented.

What you'll learn

  • A #lang module providing a custom reader and macros; the next file starts with #lang my-lang
  • The three layers: reader, syntax-objects with precise source positions, and macros
  • You never write an evaluator: expand your syntax into Racket core and the host does the rest

Core idea

A language in Beautiful Racket has a reader that turns input into data structures, macros that give meaning and expand to Racket constructs, and a module that marks the language boundary. The book ends with packing your language with raco pkg so others can install it.

Racket#lang racket/base
(require (for-syntax racket/base))

(define (read-one in src-name)
  (read-syntax src-name in))

(module reader racket/base
  (require racket/base syntax/readerr)
  (provide read-syntax)
  (define (read-syntax src in)
    (define datum (read in))
    (datum->syntax #f `(module forms ,datum))))

Why it matters

A unique perspective: define languages by declaration. Real examples like br-fruit and br-braces show exactly which parts belong to the reader and which to macros.
