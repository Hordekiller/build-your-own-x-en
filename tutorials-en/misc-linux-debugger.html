Writing a Linux Debugger

About

A multi-part series writing a Linux debugger from scratch: ptrace to control processes, ELF to understand the binary, and DWARF for debug metadata - culminating in a usable TUI debugger.

What you'll learn

  • ptrace: attach, continue, read registers and memory
  • Breakpoints by patching instructions with 0xcc (INT3)
  • ELF and DWARF: binary format and debug info

Core idea

PTRACE_ATTACH attaches to a process, PTRACE_CONT resumes it, PTRACE_PEEKDATA reads memory and PTRACE_GETREGS gets registers. The simplest breakpoint replaces the first byte of an instruction with 0xcc and restores it after the trap (and rewinds rip by one).

C++#include <sys/ptrace.h>
#include <sys/user.h>
#include <sys/wait.h>

void continue_execution(pid_t pid) {
    if (ptrace(PTRACE_CONT, pid, nullptr, nullptr) == -1) {
        perror("ptrace CONT");
        return;
    }
    waitpid(pid, nullptr, 0);
}

void get_registers(pid_t pid, user_regs_struct& regs) {
    if (ptrace(PTRACE_GETREGS, pid, nullptr, &regs) == -1) {
        perror("ptrace GETREGS");
    }
}

Why it matters

gdb demystified: ptrace, ELF, DWARF and INT3 are all the debugger ever needed.
