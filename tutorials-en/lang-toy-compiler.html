Writing Your Own Toy Compiler Using Flex

⚙ Language: C++ 📁 Programming Language 🌐 English page 🔗 Original source
Original source: "Writing Your Own Toy Compiler Using Flex"
↗ Visit the original tutorial فارسی — Persian version

About

A small compiler built with the classic tools: Flex generates a lexer (text to tokens) and Bison generates a LALR parser. Output is real assembly.

What you'll learn

  • Writing a Flex lexer: declarations, rules and extra code sections
  • A Bison grammar with %left precedence - the same idea as a hand-written Pratt parser
  • Emitting assembly inside grammar actions: the grammar-to-code connection is the essence of a compiler

Core idea

The classic tooling path: (1) build the lexer with Flex, (2) define the grammar and AST in Bison, (3) generate assembly in actions, (4) compile and run tests.

Flex%{ #include "parser.hpp" %}    // tokens from Bison
DIGIT  [0-9]
NUMBER {DIGIT}+
%%
"+"    { return PLUS; }
"-"    { return MINUS; }
"*"    { return MULT; }
"/"    { return DIV; }
{NUMBER} { yylval.num = atoi(yytext); return NUMBER; }
[ \t\n] { /* skip whitespace */ }
.      { yyerror("invalid character"); }
%%
int yywrap(void) { return 1; }
Bison%token NUMBER
%left PLUS MINUS
%left MULT DIV
%%
expr: expr PLUS expr { $$ = gen_add($1, $3); }
    | expr MULT expr { $$ = gen_mult($1, $3); }
    | NUMBER        { $$ = gen_number($1); }
    ;
%%
int gen_number(int n) {
    printf("push %d\n", n);  // assembly for a number
    return 0;
}

Why it matters

The old tools are still the fastest way to a lexer/parser: if you just want to build a compiler quickly, this is the ideal starting point.
