The very basics of a terminal emulator

⚙ Language: C 📁 Web Server 🌐 English page 🔗 Original source
Original source: "The very basics of a terminal emulator"

About

What goes on inside a terminal emulator like xterm or st: a grid of character cells, a buffer holding the content, and an escape-sequence state machine that interprets control codes for color, cursor movement and screen clearing.

What you'll learn

  • The Cell/Buffer data model behind every terminal
  • Interpreting escape sequences with a byte state machine
  • Rendering: refresh passes over a 2D grid

Core idea

Programs like vim send byte sequences such as \x1b[31m for red; the terminal must decode them and render accordingly. The heart is a 2D array of cells - each with a character, foreground/background colors and bold/underline flags.

Ctypedef struct {
    char c;          // cell character
    int fg, bg;      // foreground / background colors
    int bold, underline;
} Cell;

typedef struct {
    int rows, cols;
    Cell** cells;
} Buffer;

void term_clear(Buffer* buf) {
    for (int y = 0; y < buf->rows; y++)
        for (int x = 0; x < buf->cols; x++) {
            buf->cells[y][x].c = ' ';
            buf->cells[y][x].fg = DEFAULT;
        }
}

Why it matters

Every operation only mutates this array and then a render pass paints it - the simple core that powers every terminal in existence.
