How X Window Managers work and how to write one

About

Write a window manager for X11: the X server handles drawing and input, while the WM - a special client - decides layouts, draws titlebars and interprets keys. Starts with a simple manager that moves and maps windows, then adds tiling and focus, plus EWMH desktop announcements.

What you'll learn

  • The X11 division of labor: X server vs window manager
  • Handling MapRequest, ConfigureRequest and KeyPress events with xcb
  • Tiling behavior and the EWMH protocol for modern desktops

Core idea

The WM listens for MapRequest (a new window wants to be seen) and ConfigureRequest (a window wants size/position); the classic first step is forcing every window to fullscreen - the seed of all tiling managers.

C++#include <xcb/xcb.h>

while ((e = xcb_wait_for_event(conn))) {
    switch (e->response_type & ~0x80) {
    case XCB_MAP_REQUEST:
        map_request(conn, (xcb_map_request_event_t*)e);
        break;
    case XCB_CONFIGURE_REQUEST:
        configure_request(conn, (xcb_configure_request_event_t*)e);
        break;
    case XCB_KEY_PRESS:
        handle_key(conn, (xcb_key_press_event_t*)e);
        break;
    }
    free(e);
}

Why it matters

You use a window manager every day; writing one reveals the ancient protocol under every desktop environment.
