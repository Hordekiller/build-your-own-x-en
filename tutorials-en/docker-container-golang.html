Build Your Own Container Using Less than 100 Lines of Go

About

A container in under 100 lines of Go: fork into new namespaces, pivot_root into a filesystem, and communicate with a tiny init process over a pipe.

What you'll learn

  • The namespaces that make a container: UTS, PID, mount and more
  • pivot_root and the never-mount-over-the-runner trick
  • Why the client/server process pair is the heart of runc
  • Cleaning up: unmounting and exiting with a clean root

Core idea

The transformation happens in one triad of calls — bind the new root, pivot, and change directory before anything else can touch the old one:

And the whole program is a two-phase dispatch: run creates the child, child builds the world it will live in.

Gomust(syscall.Mount("rootfs", "rootfs", "", syscall.MS_BIND, ""))
must(os.MkdirAll("rootfs/oldrootfs", 0700))
must(syscall.PivotRoot("rootfs", "rootfs/oldrootfs"))
must(os.Chdir("/"))
Gofunc main() {
	switch os.Args[1] {
	case "run":
		parent()
	case "child":
		child()
	default:
		panic("wat should I do")
	}
}

Why it matters

The mental model of `docker run` collapses to ~100 lines of Go once you know which syscalls to ask for — the shortest path from curiosity to kernel-level containers.
