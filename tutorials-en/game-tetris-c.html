On Tetris and Reimplementation

About

The author wrote Tetris years ago and this article retells the rewrite: what was wrong in v1, lessons learned, and how v2 got a clean architecture - tetris.c (pure game logic, no UI) plus main.c (ncurses display layer).

What you'll learn

  • Separating pure game logic (board, tetrominoes, rotation, collision) from the UI
  • 7 tetrominoes as 4x4 matrices; line clearing bottom-up with row shifting
  • An ncurses layer: initscr, non-blocking keys and level-based speed

Core idea

The board is a 20x10 matrix; pieces are predefined 4x4 shapes. Collision checks shape cells against the board; clear_lines scans bottom-up and shifts rows down. The UI only does ncurses rendering and input.

C// tetris.c - pure game logic
static int board[BOARD_ROWS][BOARD_COLS];

// 7 tetrominoes as 4x4 matrices (with all rotations)
typedef struct { int shape[4][4]; } Tetromino;
static const Tetromino pieces[] = { /* I, O, T, S, Z, J, L */ };

// does the piece collide with the board or placed pieces?
static int collides(const Tetromino *p, int row, int col) {
  for (int r = 0; r < 4; r++)
    for (int c = 0; c < 4; c++)
      if (p->shape[r][c] && (board[row + r][col + c] || out_of_bounds))
        return 1;
  return 0;
}

// clear full lines - bottom up
static int clear_lines(void) {
  int cleared = 0;
  for (int r = BOARD_ROWS - 1; r >= 0; r--) {
    if (row_full(r)) { shift_rows_down(r); cleared++; r++; }
  }
  return cleared;
}

Why it matters

A clean two-file architecture: pure logic you can reuse anywhere plus a minimal terminal UI - a complete Tetris you can build with make.
