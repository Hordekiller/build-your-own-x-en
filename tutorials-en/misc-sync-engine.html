Build a Synchronization Engine with Node.js and Y.js

⚙ Language: Node.js 📁 Web Server 🌐 English page 🔗 Original source

About

A synchronization engine with CRDTs (Yjs): every device keeps a local copy, changes are updates with versions and device ids, and merging any two states always converges - conflict-free by construction.

What you'll learn

  • What CRDTs are and why merges never conflict
  • Yjs: applyUpdate, encodeStateAsUpdate, broadcast
  • The pattern: state sync first, update sync after

Core idea

The server is only an event center (relay) broadcasting changes between clients without knowing the content. New clients receive the full state, then only deltas - Yjs's state sync + update sync protocol.

JavaScriptconst Y = require('yjs');
const ws = require('ws');

// one shared document on the server
const doc = new Y.Doc();

// a client sent a change: merge it in, broadcast the result
function handleMessage(conn, data) {
    Y.applyUpdate(doc, data);   // merge into the server doc
    broadcast(doc);             // send the new state to everyone
}

// freshly connected client: full state, not a delta
function onConnect(conn) {
    conn.send(Y.encodeStateAsUpdate(doc));   // state sync
}

Why it matters

Offline-first apps like Google Docs work because of this idea - the 'last write wins' mess solved mathematically.
