Baby's First Garbage Collector

⚙ Language: C 📁 Programming Language 🌐 English page 🔗 Original source
Original source: "Baby's First Garbage Collector"

About

When you write your own interpreter, nobody cleans up objects for you. This article by Bob Nystrom builds a simple mark-and-sweep garbage collector in under 100 lines of C.

What you'll learn

  • What counts as "live": objects reachable from roots (the VM stack)
  • The two GC phases: mark (walk the object graph from roots) and sweep (free unmarked objects)
  • The classic pitfall: a new object not yet pushed onto the stack would be collected

Core idea

Every object has a marked flag. The collector marks everything reachable from the VM stack, then sweeps the full object list freeing unmarked objects. The article's trick for the "new object" problem is to attach an object directly to the root at allocation time so it can never be swept.

Ctypedef struct sObject {
    struct sObject* next;   // linked list of all objects
    char marked;            // mark flag
    int value;              // payload
} Object;

void gc() {
    // 1) mark: start from the roots (VM stack)
    for (Object* o = vm.stack; o != NULL; o = o->next)
        mark(o);
    // 2) sweep: free every unmarked object
    Object** obj = &vm.objects;
    while (*obj != NULL) {
        if (!(*obj)->marked) {
            Object* unreached = *obj;
            *obj = unreached->next;
            free(unreached);
        } else {
            (*obj)->marked = 0;
            obj = &(*obj)->next;
        }
    }
}

Why it matters

In one hour of reading you go from zero to a real GC: it explains why high-level languages insist on automatic memory management.
