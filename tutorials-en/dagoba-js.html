Dagoba: an in-memory graph database

About

Dagoba is a tiny in-memory graph database inspired by TinkerPop, shipped complete with its query language Gremlin's essence: graph traversal through a LazyQuery pipeline, plus mutation, time travel and persistence tricks — all in about 500 lines.

What you'll learn

  • Graph data as vertices and edges with schema validation.
  • A fluent query language you build from primitives.
  • Lazy evaluation: queries as async streams of results.
  • Recipe-style extras: time travel, hash-consing, serialization.

Core idea

A familiar starting point — a graph query is a path through connected vertices:

textselect ?name
where {
    ?vertex1 has name "Alice"
    ?vertex1 knows ?vertex2
    ?vertex2 has name ?name
}

And its Gremlin-flavored translation, built in Dagoba from our own query primitives:

jsvar V = g.addV('vertex', 'person');   // vertices...
var E = g.addE('edge', 'knows');      // ...and edges

P = Dagoba.P // the query primitives

g.V().has('name', 'Alice')     // start from Alice
 .out('knows')                 // follow "knows" edges
 .has('name')                  // keep vertices with a name
 .run()                        // lazy evaluation kicks in
 .map(function(vertex) {       // producers are async
   return vertex.name
 })

Why it matters

Graph databases answer questions SQL struggles with: friends-of-friends, shortest paths, recommendation walks. Dagoba shows the query language and the lazy pipeline that power the real ones, in five hundred readable lines.
