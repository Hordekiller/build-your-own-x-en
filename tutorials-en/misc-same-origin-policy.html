The Same-Origin Policy

⚙ Language: Alloy 📁 Web Server 🌐 English page 🔗 Original source
Original source: "The Same-Origin Policy"

About

A formal study of the browser's Same-Origin Policy modeled in Alloy. Shows that 'origin' is subtler than it looks: protocol + host + port matter, document.domain changes the game, and security properties can be proven by exhaustively searching all possible browser states.

What you'll learn

  • What an origin is - and the tricky edge cases
  • Modeling a security policy with Alloy signatures and relations
  • Proving which accesses the policy allows or denies

Core idea

JavaScript loaded from one origin must not access data of another. With Alloy you define signatures and relations, then let the model checker explore every combination of tabs, origins and document.domain settings.

Alloy// an origin: protocol + host + port
sig Origin {}

sig Document {
  origin: one Origin,
  domain: one Origin   // document.domain can be relaxed
}

// can script d1 read data of d2?
pred canRead[d1, d2: Document] {
  d1.domain = d2.domain
}

run canRead for 3

Why it matters

Even 'obvious' security concepts become precisely testable once encoded formally - a skill most web developers never learn.
