Demystifying compilers by writing your own

⚙ Language: Elixir 📁 Programming Language 🌐 English page 🔗 Original source
Original source: "Demystifying compilers by writing your own"

About

A video showing how to write a compiler in Elixir, the functional, pattern-matching language built on Erlang/OTP - ideal for writing readable lexers and parsers.

What you'll learn

  • The three pipeline stages: lexing, parsing (AST) and code generation
  • Writing pure functions with pattern matching, e.g. a lexer as a recursive function
  • Designing for errors: unknown tokens, unclosed parens and so on

Core idea

Everything is written as pure functions with pattern matching: the lexer consumes binary input clause by clause; the parser builds an AST with structs and recursion; the final stage emits bytecode or evaluates directly.

Elixirdefmodule Lexer do
  @digits ~r/^[0-9]/

  def tokenize(str), do: tokenize(str, [])
  defp tokenize("", acc), do: Enum.reverse(acc)

  # numbers: several digits in a row
  defp tokenize(<<c::utf8, rest::binary>>, acc) when c in ?0..?9 do
    {num, rest2} = take_digits(<<c::utf8>> <> rest, "")
    tokenize(rest2, [{:number, String.to_integer(num)} | acc])
  end

  # operators
  defp tokenize(<<"+", rest::binary>>, acc), do: tokenize(rest, [{:plus, "+"} | acc])
  defp tokenize(<<"-", rest::binary>>, acc), do: tokenize(rest, [{:minus, "-"} | acc])
  defp tokenize(<<_, rest::binary>>, acc), do: tokenize(rest, acc)  # whitespace
end

Why it matters

For Elixir fans: this video teaches both compiler principles and Elixir skills. True beginners should start with a simpler interpreter first.
