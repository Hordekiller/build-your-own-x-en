About

A step-by-step implementation of your own memory allocator: the heap is nothing but pages of memory borrowed from the operating system, organized into blocks you manage yourself.

What you'll learn

  • How the operating system hands memory to a process with sbrk()
  • Keeping the heap as a linked list of blocks with a metadata header
  • Searching, splitting and marking blocks free
  • Detecting invalid pointers with a magic marker

Core idea

The allocator asks the OS for a 4 KB page on its first call, then carves blocks out of it. Every request walks the block list looking for a fitting free block; if none exists, the allocator simply grows the heap with another sbrk() call.

Why it matters

Writing malloc demystifies pointers, heap metadata and fragmentation — and shows that 'free memory' is a data structure you fully control.
