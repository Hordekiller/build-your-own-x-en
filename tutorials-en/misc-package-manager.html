Tiny Package Manager: Learns how npm or Yarn works

About

Build an npm-like package manager step by step: parse package.json, resolve dependency versions (semver ranges compared by major.minor.patch), walk the dependency graph with BFS and write a lockfile for reproducible installs.

What you'll learn

  • The three jobs: read manifests, resolve, install into node_modules
  • semver range resolution: ^4.17.0 means >= 4.17.0 < 5
  • The dependency tree, BFS solving and the lockfile

Core idea

Dependency resolution is the real complexity: comparing version components, filtering ranges, walking the graph. The challenge npm/pnpm solved: two packages may want different versions of a shared dependency - dedupe vs separate folders.

TypeScript// compare two semver versions like "2.1.4" and "2.2.0"
function compareVersions(a: string, b: string): number {
    const pa = a.split('.').map(Number);
    const pb = b.split('.').map(Number);
    for (let i = 0; i < 3; i++) {
        if (pa[i] !== pb[i]) return pa[i] - pb[i];
    }
    return 0;
}

// "^4.17.0": major=4, highest available version
function resolveRange(range: string, versions: string[]): string {
    const [major] = range.slice(1).split('.').map(Number);
    return versions
        .filter(v => Number(v.split('.')[0]) === major)
        .sort(compareVersions)
        .pop()!;
}

Why it matters

Every install you've ever run is this algorithm at scale: manifests, semver and a graph.
