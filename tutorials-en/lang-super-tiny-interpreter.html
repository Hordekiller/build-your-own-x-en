The Super Tiny Interpreter

Original source: "The Super Tiny Interpreter"

About

The companion to the Super Tiny Compiler: instead of generating code from the AST, this project directly evaluates it - making the compiler vs interpreter comparison tangible.

What you'll learn

  • The same tokenizer/parser as the compiler, then an evaluator walking the AST
  • An environment table holding variable values; interpret recurses per node type
  • Compiler output = code; interpreter output = value - and JITs combine both

Core idea

The heart is a recursive interpret function: NumberLiteral returns its value, CallExpression evaluates each argument then looks up and calls the function from the environment.

JavaScriptfunction interpret(ast, env = {}) {
  const node = ast;
  switch (node.type) {
  case 'NumberLiteral':
    return Number(node.value);
  case 'CallExpression': {
    // evaluate each argument
    const args = node.arguments.map(arg => interpret(arg, env));
    // find the function in the environment (add, subtract, ...)
    const func = env[node.callee];
    if (typeof func !== 'function')
      throw new Error('function ' + node.callee + ' is not defined');
    return func.apply(null, args);
  }
  default:
    throw new Error('unknown node: ' + node.type);
  }
}

// initial environment: basic functions
const env = { add: (a, b) => a + b, subtract: (a, b) => a - b };
const ast = parse(tokenize('(add 2 (subtract 4 2))'));
console.log(interpret(ast, env));  // 4

Why it matters

The perfect next step after the compiler to understand execution costs; the same symbol-table-and-recursion pattern scales up to real interpreters like jlox.
