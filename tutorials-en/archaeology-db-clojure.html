An Archaeology-Inspired Database

⚙ Language: Clojure 📁 Database 🌐 English page 🔗 Original source
Original source: "An Archaeology-Inspired Database" — the 500 Lines chapter by Timothy Toolan: a Datomic-inspired database with four four-dimensional indexes and historical time travel.
↗ Visit the original tutorial فارسی — Persian version

About

A truly different database design: inspired by archaeologists and Datomic, every fact ever written is kept, and reads can travel back in time. Data is organized in layers, entities, attributes with timestamps, and four query indexes (EAVT, AEVT, VAET, AVET).

What you'll learn

  • A temporal, append-only data model — time travel reads.
  • Entities and attributes with type, value and timestamps.
  • The four index orders and which queries they answer.
  • Query semantics over a persistence layer protocol.

Core idea

The entire database is two record types — the database itself and its layers:

clj(defrecord Database [layers top-id curr-time])
(defrecord Layer [storage VAET AVET VEAT EAVT])

Entities carry their attributes, and attributes remember their history:

clj(defrecord Entity [id attrs])
(defrecord Attr [name value ts prev-ts])

(defn make-attr
   ([name value type ; these are required
       & {:keys [cardinality] :or {cardinality :db/single}} ]
     {:pre [(contains? #{:db/single :db/multiple} cardinality)]}
    (with-meta (Attr. name value -1 -1) {:type type :cardinality cardinality})))

Storage itself is a protocol — you can plug any backing implementation behind it:

clj(defprotocol Storage
   (get-entity [storage e-id])
   (write-entity [storage entity])
   (drop-entity [storage entity]))

Why it matters

It breaks the assumption that a database must delete. The datalog-inspired query model and temporal layers are genuinely production ideas (Datomic), presented in a compact 500-line implementation.
