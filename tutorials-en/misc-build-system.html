Writing a Build system

⚙ Language: Nim 📁 Web Server 🌐 English page 🔗 Original source
Original source: "Writing a Build system"
↗ Visit the original tutorial فارسی — Persian version

About

Build a build system in Nim, the make/ninja idea in miniature: tasks with dependencies, executed in the right order, each task run only once even if referenced several times.

What you'll learn

  • A Task type: name, dependency list and action closure
  • Topological execution with a built set to skip repeats
  • How this mirrors make's targets without Makefile parsing

Core idea

build(name) recurses into dependencies first, then runs the action - and the built set makes the dependency graph loop-free and re-run-free.

Nimimport tables, sets

type Task = ref object
  name: string
  deps: seq[string]
  action: proc()

var tasks = initTable[string, Task]()
var built = initHashSet[string]()

proc task(name: string, deps: seq[string] = @[], action: proc()) =
  tasks[name] = Task(name: name, deps: deps, action: action)

proc build(name: string) =
  if name in built: return       # skip repeats
  built.incl(name)
  let t = tasks[name]
  for d in t.deps: build(d)      # dependencies first
  t.action()                     # then the task itself

Why it matters

Dependency resolution is the exact algorithm make runs - without the Makefile syntax noise.
