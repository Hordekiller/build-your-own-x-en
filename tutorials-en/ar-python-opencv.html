Augmented Reality with Python and OpenCV

⚙ Language: Python 📁 Augmented Reality 🌐 English page 🔗 Original source
Original source: "Augmented Reality with Python and OpenCV" — a two-part series on marker-based augmented reality by Bites of Code (Sergio Canu).
↗ Visit the original tutorial فارسی — Persian version

About

Unlike the Unity-based AR tutorials, this series builds augmented reality with pure computer vision: Python and OpenCV, with the math spelled out. You place a flat reference surface in front of the camera, estimate the homography between the reference and the image, extract the camera pose, and render a 3D model over the video feed — marker-based AR, from first principles.

What you'll learn

  • Detecting a reference plane in the camera image.
  • Estimating the homography with keypoint matching and RANSAC.
  • Deriving the camera's calibration matrix.
  • Extracting rotation and translation (the pose) from the homography.
  • Projecting a 3D model into the image and drawing it per frame.

The pipeline

The first part ends with a clear road map of the whole system; the second part executes every step:

  1. Derive the camera model — at this point everything is unknown.
  2. Estimate the homography empirically via keypoints and RANSAC — the homography is no longer unknown.
  3. Estimate the camera calibration matrix — now the intrinsic matrix is known.
  4. Recover pose: combine the homography, the calibration matrix and the camera model to compute rotation directions and translation.
  5. Render the 3D model in the pixel space and draw it.

Core idea

The pipeline starts by detecting ORB keypoints in the camera frame:

pythonimg = cv2.imread('scene.jpg', 0)

# Create an ORB detector
orb = cv2.ORB_create()

# Find keypoints with ORB
kp = orb.detect(img, None)

# Compute descriptors with ORB
kp, des = orb.compute(img, kp)

# Draw only the location of keypoints, not their size and orientation
img2 = cv2.drawKeypoints(img, kp, img, color=(0,255,0), flags=0)
cv2.imshow('keypoints', img2)
cv2.waitKey(0)

Next, keypoints are matched against the reference image, and a homography is computed — the transform that tells you where the 3D content must be drawn:

Why it matters

Commercial AR SDKs must feel like magic; this series removes the illusion. Understanding homography and pose estimation is the foundation not only of AR, but of camera calibration, Structure-from-Motion and robotics — and the Python code lets you run the whole pipeline on a webcam today.
