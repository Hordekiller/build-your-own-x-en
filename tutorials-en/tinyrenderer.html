How OpenGL works: software rendering in 500 lines of code

⚙ Language: C++ 📁 3D Renderer 🌐 English page 🔗 Original source
Original source: "How OpenGL works: software rendering in 500 lines of code" by Dmitry Sokolov (ssloy) — walk through the entire tinyrenderer wiki on GitHub.
↗ Visit the original tutorial فارسی — Persian version

About

"Tinyrenderer" is one of the most famous build-your-own renderer series. It walks through the internals of OpenGL by implementing a software rasterizer from absolute zero: no graphics libraries, no external dependencies — just C++ and hand-written math, ending with a shaded, textured 3D head rendered to a TGA image file.

What you'll learn

  • Drawing lines: from a naive interpolation to Bresenham's algorithm.
  • Filling triangles: scanlines and barycentric coordinates, and why the latter is cleaner.
  • Z-buffering: the hidden-surface solution that makes depth ordering just work.
  • Lighting: Gouraud versus Phong shading, normals and the diffuse term.
  • Perspective projection: the viewport, camera math and the z-divide.
  • Texture mapping, shaders, and the classic "look at" camera.

Core idea

Everything starts with a framebuffer: an array of pixels that the CPU itself writes to. The very first lesson fills a single pixel, the second draws a line, and step by step the pipeline of a real GPU is reconstructed in about 500 lines.

cpp#include "tgaimage.h"
const TGAColor white = TGAColor(255, 255, 255, 255);
const TGAColor red   = TGAColor(255, 0,   0,   255);
int main(int argc, char** argv) {
        TGAImage image(100, 100, TGAImage::RGB);
        image.set(52, 41, red);
        image.flip_vertically(); // want the origin at bottom-left
        image.write_tga_file("output.tga");
        return 0;
}

A 100×100 image, one red pixel, saved as TGA — the entire "GPU" is a plain array of bytes.

A line, then a triangle

The line-drawing lesson is a history of optimization in miniature: first a slow parametric loop, then integer math, then Bresenham. Triangles are filled with barycentric coordinates — a test of whether a pixel lies inside a triangle — which later becomes the basis for interpolating colors, normals and textures across a face.

cppvoid line(int x0, int y0, int x1, int y1, TGAImage &image, TGAColor color) {
    for (int x=x0; x<=x1; x++) {
        float t = (x-x0)/(float)(x1-x0);
        int y = y0*(1.-t) + y1*t;
        image.set(x, y, color);
    }
}

Why it matters

After tinyrenderer, graphics APIs stop being magic: you know exactly what a shader is, what a vertex transform does, and why the z-buffer exists. It is also the perfect bridge to modern GPU programming, making OpenGL/Vulkan calls comprehensible as "the hardware version of the software you just wrote".
