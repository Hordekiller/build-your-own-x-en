Writing a MiniTest Framework

⚙ Language: Nim 📁 Web Server 🌐 English page 🔗 Original source
Original source: "Writing a MiniTest Framework"
↗ Visit the original tutorial فارسی — Persian version

About

A MiniTest framework in Nim with RSpec-like syntax built from macros: describe/test blocks are collected at compile time, run one by one, and report a summary with a nonzero exit on failure - the CI contract.

What you'll learn

  • A testing framework's parts: registration, isolation, assertions, summary
  • Nim macros as DSLs: turning describe/test syntax into registrations
  • quit(1) on failure - what CI pipelines actually check

Core idea

A macro walks the AST of describe blocks and emits tests.add(...) calls, so the DSL costs nothing at runtime. CatchableError catches failures per test.

Nimimport macros

var tests: seq[(string, proc())]

macro describe(name: static[string], body: untyped): untyped =
  result = newStmtList()
  for child in body:
    if child.kind == nnkCall and child[0].repr == "test":
      let testName = child[1].repr
      let body = child[2]
      result.add newCall(ident"tests.add",
        newTree(nnkTupleConstr, newLit(testName), body))

var passed = 0
var failed = 0
for (name, body) in tests:
  try:
    body()
    passed.inc
    echo "ok ", name
  except CatchableError as e:
    failed.inc
    echo "FAIL ", name, " - ", e.msg

echo passed, " passed, ", failed, " failed"
if failed > 0: quit(1)    # important for CI!

Why it matters

You use test frameworks daily; a macro-based one shows how 'languages on the language' are built at compile time.
