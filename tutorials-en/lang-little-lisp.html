Little Lisp interpreter

About

Mary Rose Cook proved that building a Lisp interpreter in JavaScript is simple: the whole project is four functions - tokenize, parse, evaluate and apply.

What you'll learn

  • Parsing tokens into a tree, with recursion handling nested parens
  • An environment as a name-to-value table; closures with apply
  • That Lisp is recursive rules, not magic - lambda/define/begin are just patterns

Core idea

parse turns tokens into nested lists (returning a list at '('); evaluate walks the tree: atoms are numbers or variable lookups, lists call the first element with the rest as arguments. Environments and closures come naturally.

JavaScriptfunction parse(tokens, memory) {
  if (typeof memory === 'undefined') { memory = { index: 0 }; }
  if (tokens[memory.index] === '(') {
    // start of a list
    memory.index++;
    let list = [];
    while (tokens[memory.index] !== ')') {
      list.push(parse(tokens, memory));  // recursion for each element
    }
    memory.index++;  // skip ')'
    return list;
  } else if (tokens[memory.index] === ')') {
    throw new Error('extra paren!');
  } else {
    const atomicToken = tokens[memory.index++];
    return atomicToken;  // atom: name or number
  }
}
JavaScriptfunction evaluate(ast, environment) {
  if (typeof environment === 'undefined') {
    environment = globalEnvironment;
  }
  // atoms
  if (typeof ast === 'string') {
    if (isNaN(parseInt(ast))) return lookupVariable(ast, environment);
    return parseInt(ast);
  }
  // list: operator and arguments
  const operator = ast[0];
  const operands = ast.slice(1);
  if (operator === 'define') {
    environment[operands[0]] = evaluate(operands[1], environment);
    return environment[operands[0]];
  }
  if (operator === 'begin') {
    return operands.reduce((last, exp) => evaluate(exp, environment), undefined);
  }
  const closure = evaluate(operator, environment);
  const args = operands.map(o => evaluate(o, environment));
  return closure.apply(null, args);
}

Why it matters

The best starting point for a JavaScript Lisp interpreter: short, readable and complete (variables + functions). Continue with Crafting Interpreters or mal for closures and GC.
