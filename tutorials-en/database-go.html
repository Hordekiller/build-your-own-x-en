About

A relational database in about 3000 lines of Go, developed in 12 parts: crash-safe persistence, perfectly sized pages, B-tree and B+tree inner workings, freelists, transaction records, recovery, versioned pages, a key-value API, tables and records, secondary indexes, and finally SQL — query parser and execution engine included.

What you'll learn

  • Crash-safe storage: atomic writes, COW, fsync.
  • Why databases use trees — the B+tree in depth.
  • MVCC, versioned pages and transaction recovery.
  • Turning a key-value store into SQL with indexes and a query engine.

Core idea

Durability without corruption: never overwrite live data — write to a temporary file, then atomically rename:

gofunc SaveData2(path string, data []byte) error {
    tmp := fmt.Sprintf("%s.tmp.%d", path, randomInt())
    fp, err := os.OpenFile(tmp, os.O_WRONLY|os.O_CREATE|os.O_EXCL, 0664)
    if err != nil {
        return err
    }
    defer func() { // 4. discard the temporary file if it still exists
        fp.Close()
        os.Remove(tmp)
    }()
    _, err = fp.Write(data)
    if err != nil {
        return err
    }
    // 1. flush to disk
    err = fp.Sync()
    if err != nil {
        return err
    }
    // 2. close to flush metadata
    err = fp.Close()
    if err != nil {
        return err
    }
    // 3. and rename into place
    return os.Rename(tmp, path)
}

Updates are log-structured: new versions accumulate, later ones win:

Why it matters

This is the rare end-to-end journey: by the last chapters you have executed actual SQL — parsing, planning, and evaluating queries against your own B+tree — the complete anatomy of a production-style database.
