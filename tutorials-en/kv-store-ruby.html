Build your own fast, persistent KV store in Ruby

About

A Bitcask-inspired key-value store in Ruby: writes are appends to a log, a hash index in memory points at each key's timestamp, size and offset in the data file, and all records roll forward under CRC32 checks. Fast to read, fast to write, persistent by construction.

What you'll learn

  • Append-only, log-structured storage (Bitcask's model).
  • In-memory index → file offsets: the two-level lookup.
  • Binary serialization: headers, CRCs, type tags.
  • Writing compact Ruby modules for both.

Core idea

First, the premise — appended data beats overwriting:

rbFile.open('sample.txt', 'w') do |file|
    [1, 12, 123, 1234, 12345, 123456, 1234567, 12345678].each do |num|
        file.write(num)
    end
end

Then the serializer — a fixed header and a zlib-guarded body:

rbmodule Bitcask
  module Serializer

    HEADER_FORMAT = 'L<L<L<S<S<'
    HEADER_SIZE = 16

    def serialize(epoch:, key:, value:)
      key_type = type(key)
      value_type = type(value)

      key_bytes = pack(key, key_type)
      value_bytes = pack(value, value_type)

      header = serialize_header(
        timestamp: epoch,
        key_size: key_bytes.size,
        value_size: value_bytes.size,
        key_type: key_type,
        value_type: value_type
      )

      crc32 = [Zlib.crc32(header + key_bytes + value_bytes)].pack('L')
      crc32 + header + key_bytes + value_bytes
    end

Why it matters

Bitcask's design powers Riak's production storage; Redis was once described as a similar idea. This post distills that mature, battle-tested design into an afternoon of Ruby — a masterpiece of applied simplicity.
