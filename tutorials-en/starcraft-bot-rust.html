A bot for Starcraft in Rust, C or any other language

About

A different kind of bot: an AI crew member for StarCraft II, written in Rust. Along the way it teaches Rust's foreign function interface — calling C libraries like snappy — which is the foundation of how Rust games and engines bind native code.

What you'll learn

  • Scaffolding a Rust binary project with cargo.
  • Declaring C functions with the extern block.
  • Linking a C library with #[link].
  • Bringing a theory into a running game bot.

Core idea

The project starts as one cargo binary and one dependency — libc for the C types:

shell$ cargo new --bin snappy
     Created binary (application) `snappy` project
$ cd snappy
snappy$ tree
.
├── Cargo.toml
└── src
    └── main.rs

1 directory, 2 files
toml[dependencies]
libc = "0.2"

Calling into a C library from Rust is explicit: name the library, declare the function, and cargo links it at build time:

rustextern crate libc; // to import C types; in our case for size_t
use libc::size_t;

#[link(name = "snappy")] // specifies the library name to link the function from
extern {
    // declare the function we want to import;
    // in C this declaration looks like:
    // size_t snappy_max_compressed_length(size_t source_length);
    fn snappy_max_compressed_length(source_length: size_t) -> size_t;
}

Why it matters

FFI is how Rust talks to the entire C universe — game engines, OS libraries, native codecs. Doing it once with a tiny library removes the mystery and quietly prepares you for serious Rust systems work.
