DBDB: Dog Bed Database

⚙ Language: Python 📁 Database 🌐 English page 🔗 Original source
Original source: "DBDB: Dog Bed Database" — the 500 Lines chapter by Taavi Burns: a beefed-up BTrees persistent key-value store, directly inspired by basho's Bitcask and couchdb's BTree storage.
↗ Visit the original tutorial فارسی — Persian version

About

DBDB is a persistent, on-disk key-value store written in Python — a dictionary whose data survives restarts. Built from two production ideas: Bitcask's write-once behavior and the BTree's ordered, log-structured nodes, with a sorting layer, physical storage, binary serialization and crash-safety built in.

What you'll learn

  • Persistent data structures: writing state that survives crashes.
  • Logical vs. physical data views and the sorting layer between them.
  • BTrees: nodes, serialization and on-disk layout.
  • The interface that makes a library feel like a CLI database.

Core idea

The database is used from a shell like any serious engine:

shell$ python tool.py
> db = connect('mydogdb')
> db['a'] = '1'
> db['a']
'1'

And its heart is the tool module — the user-facing door to the whole engine:

pythonfrom dbdb.interface import connect
from dbdb.tool import main

Underneath: a sorting layer (one key: from logical to physical), a physical layer (serializing to / deserializing from binary), and a BTree storing redundant, ordered data — mirrored, log-structured, crash-safe.

Why it matters

Two production patterns are torn down and rebuilt in Python: Bitcask's append-only write philosophy and the BTree's ordered persistence. The result is a real dictionary that survives `Ctrl-C` — and the mental model transfers to any embedded database.
