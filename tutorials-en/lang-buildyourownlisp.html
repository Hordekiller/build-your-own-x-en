Build Your Own Lisp: Learn C and build your own programming language in 1000 lines of code

About

Daniel Holden builds a complete Lisp - Lispy - from scratch assuming the reader knows no C at all, ending with a REPL supporting functions, variables, conditionals and lambdas.

What you'll learn

  • Building the mpc parser-combinator library inside the book to define the language grammar
  • Polish notation and a recursive grammar: expr can contain expr
  • Evaluation: q-expressions (unquoted lists) make list/head/tail possible; later def, lambda and a small GC

Core idea

The book starts with a Polish-notation calculator (+ 1 (* 2 3)) and defines the grammar with mpc's mpc_parser_t. Once mpc produces a syntax tree, an eval function picks the operator, recursively evaluates arguments and calls it. Later chapters add q-expressions, variables with def, lambdas with \, error handling and a simple standard library.

Cmpc_parser_t* Number   = mpc_new("number");
mpc_parser_t* Operator = mpc_new("operator");
mpc_parser_t* Expr     = mpc_new("expr");
mpc_parser_t* Lispy    = mpc_new("lispy");
mpca_lang(MPCA_LANG_DEFAULT,
  " number : /-?[0-9]+/ ;"
  " operator : '+' | '-' | '*' | '/' ;"
  " expr : <number> | '(' <operator> <expr>+ ')' ;"
  " lispy : /^/ <operator> <expr>+ /$/ ;",
  Number, Operator, Expr, Lispy);
Clval* eval(lval* v) {
    if (v->type == LVAL_NUM) return v;         // number: final value
    lval* f = pop(v, 0);                        // take the operator
    for (int i = 0; i < v->count; i++)
        v->cell[i] = eval(v->cell[i]);          // recursive args
    return call(f, v);                          // run the function
}

Why it matters

The best choice for a complete beginner: you start with C and finish with a Lisp interpreter that has functions and variables, understanding parser, AST, eval and REPL deeply.
