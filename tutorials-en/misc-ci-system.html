About

The CI chapter from 500 Lines: a continuous integration system - a server that records and reports build statuses, runners that execute tests on any machine, and publishers that push events to email/IRC - with the Observer pattern.

What you'll learn

  • The two-component architecture: server + runner
  • The Observer pattern: BuildStatus notifying subscribers
  • Runner tests on threads with timeouts so hangs can't lock CI

Core idea

Each test run is a Build with states; set_status notifies subscribers immediately - no polling loops. Tests run on separate threads with a timeout to survive hung tests.

Pythonclass BuildStatus:
    """the status of a build that notifies its subscribers."""
    def __init__(self, name):
        self.name = name
        self.status = 'pending'
        self.subscribers = []

    def subscribe(self, sub):
        self.subscribers.append(sub)

    def set_status(self, status):
        self.status = status
        for sub in self.subscribers:
            sub(self)   # notify: this build reached a status

Why it matters

GitHub Actions demystified: a status object, a runner and subscribers - the pull-based alternative to polling.
