Building Your Own Kafka-like System From Scratch: A Step-by-Step Guide

About

This guide walks you through building a simplified Apache Kafka clone in Java — a distributed message broker where producers write records to topics and consumers read them back, all while data is stored in an append-only log. The project targets developers who understand Kafka's terminology (brokers, topics, partitions, offsets) and want to see how these pieces actually work under the hood.

By the end you will have a working system: multiple broker processes coordinated through ZooKeeper, a producer that assigns partitions and publishes records, and a consumer that pulls records by offset — plus the tests that keep it honest.

What you'll learn

  • Broker architecture: how a broker stores records in an append-only log and serves consumers by offset.
  • ZooKeeper coordination: registering brokers, tracking partition ownership and handling leader election.
  • Producer side: serializing records, partitioning them across brokers and acknowledging writes.
  • Consumer side: subscribing to topics, tracking the current offset and reading records in order.
  • Multi-broker setup: running several brokers on one machine and observing how they cooperate.

Core idea

The heart of Kafka is the log: records are only ever appended, and consumers remember where they stopped. This tutorial rebuilds that model in plain Java — a broker class backed by a log file, and client classes that talk to it over TCP.

bash# Terminal 1 — broker 1
java -cp target/simple-kafka-1.0-SNAPSHOT.jar com.simplekafka.broker.SimpleKafkaBroker 1 localhost 9091 2181

# Terminal 2 — broker 2
java -cp target/simple-kafka-1.0-SNAPSHOT.jar com.simplekafka.broker.SimpleKafkaBroker 2 localhost 9092 2181

# Terminal 3 — broker 3
java -cp target/simple-kafka-1.0-SNAPSHOT.jar com.simplekafka.broker.SimpleKafkaBroker 3 localhost 9093 2181

Three broker processes, each bound to its own port, all registering themselves with a shared ZooKeeper instance — that is the whole "cluster" for this tutorial.

Producing and consuming

Once the brokers are running, the included CLI clients demonstrate the round trip: the producer publishes records to a topic, and the consumer reads them back starting from a chosen offset.

bash# Publish records to "test-topic" through broker 1
java -cp target/simple-kafka-1.0-SNAPSHOT.jar com.simplekafka.client.SimpleKafkaProducer localhost 9091 test-topic

# Read records back, starting from offset 0
java -cp target/simple-kafka-1.0-SNAPSHOT.jar com.simplekafka.client.SimpleKafkaConsumer localhost 9091 test-topic 0

Because records are stored in an append-only log, a consumer can always re-read history by replaying offsets — the same property that makes Kafka-style systems so useful for event streaming and replay.

Why it matters

Kafka's real implementation is thousands of lines of distributed-systems engineering. This project cuts through the noise and shows the essential ideas — logs, offsets, broker coordination — in a codebase small enough to read in an afternoon. Afterward, Kafka's docs and configuration options make far more sense.
