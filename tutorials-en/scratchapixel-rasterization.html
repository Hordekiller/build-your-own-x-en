Rasterization: a Practical Implementation

⚙ Language: C++ 📁 3D Renderer 🌐 English page 🔗 Original source
Original source: "Rasterization: a Practical Implementation" — a Scratchapixel lesson that contrasts rasterization with ray tracing and implements both in real code.

About

This Scratchapixel lesson answers a fundamental question — "why are there two rendering algorithms?" — and then implements both. You first write a raytracer that finds, per pixel, the closest triangle along a ray; then you flip the loops and write a rasterizer that projects every triangle and fills only the pixels inside it. Comparing the two is the fastest way to understand modern GPUs.

What you'll learn

  • The loop order that separates rasterization from ray tracing.
  • Perspective projection of 3D vertices to 2D screen coordinates.
  • The "point in triangle" test and bounding-box optimization.
  • Depth testing, the z-buffer and why GPUs need it.
  • Backface culling and vertex normals.
  • Interpolating attributes (colors, normals) across a triangle.

Core idea

Ray tracing iterates over pixels and asks which triangle they hit; rasterization iterates over triangles and fills the pixels they cover. The rasterizer version: project each vertex, clamp to the viewport, then scan only the bounding box of the projected triangle and test membership with barycentric coordinates.

pseudo// The rasterization algorithm
for (each triangle in the scene) {
    // Step 1: project the triangle's vertices with perspective projection
    Vec2f v0 = perspectiveProject(triangle[i].v0);
    Vec2f v1 = perspectiveProject(triangle[i].v1);
    Vec2f v2 = perspectiveProject(triangle[i].v2);
    for (each pixel in the image) {
        // Step 2: is this pixel inside the projected triangle?
        if (pixelContainedIn2DTriangle(v0, v1, v2, x, y)) {
            image(x, y) = triangle[i].color;
        }
    }
}

Why it matters

Because GPUs rasterize, understanding this algorithm is understanding how a graphics card actually spends its time — thousands of triangles processed in parallel, each filling its pixel footprint. Comparing it side-by-side with ray tracing also explains why real-time and offline rendering use different tools.
